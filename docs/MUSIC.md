# Музыка: импорт из Spotify, кэш и воспроизведение

Раздел **«Музыка»** превращает VibeDrop из чистого саундпада в ещё и простой плеер:
вставляете ссылку на трек, альбом или плейлист Spotify, VibeDrop читает метаданные, находит аудио в
открытых источниках, складывает MP3 в отдельный кэш и играет его через **те же два выхода**,
что и звуки саундпада (наушники и маршрут микрофона), с тем же мастер-громкостью, лимитером и
маршрутизацией.

Раздел не связан с библиотекой звуков: длинные треки не попадают в список звуков, не получают
горячих клавиш и не мешают горячим клавишам саундпада.

## Быстрый старт

1. Установите **yt-dlp** и **ffmpeg** (см. ниже) — они нужны для поиска и конвертации.
   В архивах релиза они уже лежат в папке `tools/` рядом с программой, поэтому в
   скачанной сборке этот шаг можно пропустить.
2. Откройте *Настройки → Музыка* и проверьте строку состояния: там показаны найденные версии.
   Если программы лежат не в `PATH`, укажите путь к файлу или папке.
3. Откройте раздел **«Музыка»**, вставьте ссылку вида
   `https://open.spotify.com/album/...`, `https://open.spotify.com/track/...` или
   `https://open.spotify.com/playlist/...` и нажмите **«Добавить в музыку»**.
4. Все треки сразу ставятся в очередь загрузки. У каждого трека виден статус:
   *В очереди → Качается → Готово* или *Ошибка* (с причиной в подсказке).
5. Нажмите **«Играть всё»** (или play у трека). Кнопка повтора циклически переключает
   `Repeat: Off → All → One`.

Ссылку можно вставлять и без схемы: `open.spotify.com/album/...`, а также в виде
`spotify:album:...` (для плейлиста — `spotify:playlist:...`). Короткие ссылки `spotify.link/...`
не поддерживаются: откройте такую ссылку в браузере и скопируйте итоговый адрес
`open.spotify.com/...`.

## Зависимости

VibeDrop не устанавливает эти программы сам — он только запускает то, что уже есть на
компьютере. В архивах релиза они лежат рядом с программой (папка `tools/`), поэтому в
скачанной сборке ничего доустанавливать не нужно. Лицензии и точные сборки — в
`THIRD_PARTY_NOTICES.md` и `tools/licenses/`.

### yt-dlp

Находит и скачивает аудио. Нужна свежая версия: сайты часто меняют разметку.

| Система | Команда |
| --- | --- |
| Windows (winget) | `winget install yt-dlp.yt-dlp` |
| Windows (pip) | `pip install -U yt-dlp` |
| Windows (Chocolatey) | `choco install yt-dlp` |
| macOS | `brew install yt-dlp` |
| Debian/Ubuntu | `sudo apt install yt-dlp` (если версия старая — `pipx install yt-dlp`) |
| Arch | `sudo pacman -S yt-dlp` |

Обновление: `yt-dlp -U` (или тем же пакетным менеджером).

### ffmpeg

Нужен для извлечения аудиодорожки и конвертации в MP3.

| Система | Команда |
| --- | --- |
| Windows (winget) | `winget install Gyan.FFmpeg` |
| Windows (Chocolatey) | `choco install ffmpeg` |
| macOS | `brew install ffmpeg` |
| Debian/Ubuntu | `sudo apt install ffmpeg` |
| Arch | `sudo pacman -S ffmpeg` |

Если программы распакованы вручную, укажите в *Настройках → Музыка*:
* путь к `yt-dlp.exe` (или папке, где он лежит);
* путь к `ffmpeg.exe` (или папке `bin`, где он лежит). Папка `ffmpeg-.../bin` тоже подходит.

Пустое поле = поиск в `PATH`, рядом с `vibedrop.exe`, в `%LOCALAPPDATA%\Programs\yt-dlp`,
`scoop\shims`, `chocolatey\bin`, `Python\Scripts`, `/usr/local/bin`, `/usr/bin`,
`/opt/homebrew/bin`.

## Метаданные Spotify

Поддерживаются два пути, оба **без входа в аккаунт пользователя**.

### 1. Публичная страница (по умолчанию, без ключей)

VibeDrop запрашивает `https://open.spotify.com/embed/{track|album|playlist}/{id}` и читает JSON из
`<script id="__NEXT_DATA__">`: название, исполнитель, обложка, длительность и список треков
альбома или плейлиста. Это работает сразу после установки. Минусы: страница может измениться, у
одиночного трека не всегда есть название альбома, а плейлист отдаётся одной страницей (Spotify
показывает до 100 треков).

### 2. Spotify Web API (Client Credentials, рекомендуется)

Даёт стабильный документированный ответ, название альбома трека и постраничную выдачу для
альбомов и плейлистов длиннее 50 треков.

1. Откройте <https://developer.spotify.com/dashboard> и создайте приложение
   (подойдёт любое имя; Redirect URI для Client Credentials не нужен).
2. Скопируйте **Client ID** и **Client Secret**.
3. Вставьте их в *Настройки → Музыка* или задайте переменные среды
   `SPOTIFY_CLIENT_ID` и `SPOTIFY_CLIENT_SECRET` (переменные используются, только если поля
   пусты).
4. Нажмите «Импортировать»: VibeDrop получает токен на
   `accounts.spotify.com/api/token` и читает каталог.

Важно:
* Client Credentials даёт доступ **только на чтение публичного каталога**; аккаунт Spotify и
  пользовательский вход не используются.
* Секрет хранится в открытом виде в `settings.json` в папке данных VibeDrop — это локальный
  файл пользователя. Не публикуйте его.
* Если API вернул 401/403 (неверные ключи, приложение без Web API), VibeDrop пишет
  предупреждение в лог и **автоматически** переключается на публичную страницу, поэтому
  импорт не блокируется.

### Плейлисты

Ссылка `open.spotify.com/playlist/...` (или `spotify:playlist:...`) добавляет весь плейлист
одной коллекцией: он появляется в списке рядом с альбомами со своей обложкой, названием,
числом треков, кнопками «Играть всё», «Докачать недостающие» и общим Repeat. Треки скачиваются
тем же каскадом SoundCloud → YouTube с проверкой длительности.

* С Client ID/Secret плейлист читается через `GET /playlists/{id}` постранично (до 50 страниц);
* без ключей — с публичной embed-страницы, обычно до 100 треков;
* локальные файлы плейлиста и эпизоды подкастов пропускаются;
* повторный импорт той же ссылки находит уже добавленный плейлист и только докачивает
  недостающие треки; новые треки, добавленные в Spotify позже, подхватятся после удаления и
  повторного импорта плейлиста.

## Каскадный поиск и скачивание

Один рабочий поток обрабатывает треки по одному (параллельные поиски только повышают шанс
блокировки). Для каждого трека:

1. **SoundCloud** — `yt-dlp "scsearch1:Исполнитель - Название"`.
   * Название очищается от `(Remastered 2009)`, `- Deluxe Edition`, `[Bonus Track]`, `- Live`
     и похожих пометок — иначе точное совпадение почти не находится.
   * Длительность найденного трека сравнивается с длительностью из Spotify.
     Допуск — **15 секунд**. Ремиксы, каверы и 30-секундные отрывки отсекаются.
   * Если у результата нет длительности, он не принимается: проверить совпадение нельзя.
2. **YouTube** — `yt-dlp "ytsearch1:Исполнитель - Название official audio"`.
   * Допуск — **20 секунд** (официальные загрузки иногда содержат лишнюю секунду тишины).
3. Скачивание: `yt-dlp -f bestaudio/best -x --audio-format mp3 --audio-quality 0`
   с `--ffmpeg-location <папка ffmpeg>`; результат проверяется по содержимому (MP3) перед
   добавлением в библиотеку.

Если оба источника не подошли, трек получает статус **Ошибка**, а в подсказке — причины:
«SoundCloud: ближайшее совпадение 240 с, в Spotify 214 с (допуск 15 с); YouTube: …».
Клик по чипу «Ошибка» повторяет загрузку. «Докачать недостающие» запускает все незагруженные
треки выбранного альбома или плейлиста.

Поведение при отмене/перезапуске:
* «Очистить кэш» останавливает текущую загрузку (`yt-dlp` завершается), удаляет файлы кэша и
  возвращает все треки в очередь;
* незавершённые файлы (`*.part`, `*.webm` и т. п.) удаляются;
* статус `Downloading`, сохранённый при аварийном закрытии, при следующем запуске становится
  `Queued`, а уже готовый файл подхватывается как `Ready`.

Инструменты запускаются **без shell**, с явным списком аргументов, поэтому название трека не
может стать командой. `yt-dlp` работает с `--ignore-config`: пользовательский конфиг не
меняет поведение VibeDrop неожиданным образом.

## Кэш и данные

| Что | Где |
| --- | --- |
| Метаданные коллекций и статусы | `%LOCALAPPDATA%\VibeDrop\VibeDrop\data\music.json` |
| MP3-файлы | `%LOCALAPPDATA%\VibeDrop\VibeDrop\data\music\<track-id>.mp3` |

На Linux/macOS — соответствующий `ProjectDirs` путь (`~/.local/share/VibeDrop/...` и т. п.).
Кнопка «Открыть папку данных» в настройках показывает корень. `music.json` входит в резервную
копию, которую создаёт «Экспорт копии» (сами MP3-файлы — нет: их можно скачать заново).

Ограничения:
* длительность одного трека — **15 минут** (`MAX_MUSIC_SECS` в `src/audio/engine.rs`);
* трек декодируется в память целиком, как звук саундпада; 15 минут стерео при 48 кГц — это
  около 170 МБ плюс копия под частоту конкретного выхода. Декодированный кэш ограничен
  256 МБ и вытесняет давно не использованные записи; играющий трек не выгружается;
* кэш можно очистить в любой момент — файлы удаляются, метаданные коллекций остаются.

## Воспроизведение

* Музыка играет через существующий движок (`src/audio/engine.rs`) на те же выходы:
  наушники/колонки и маршрут микрофона. Громкость = `master × громкость маршрута × громкость
  музыки` (ползунок в плеере, хранится в настройках).
* Очередь — это треки выбранного альбома или плейлиста. «Играть всё» начинает с первого, play у
  трека — с него; следующий трек запускается автоматически.
* Режимы повтора:
  * **Off** — доиграть альбом до конца и остановиться;
  * **All** — после последнего трека снова первый;
  * **One** — бесконечно повторять текущий.
* Если трек ещё не скачан, плеер переходит в состояние «Ожидание скачивания…» и стартует сам,
  как только файл готов. При ошибке загрузки текущего трека плеер показывает ошибку, а не
  зависает.
* «Стоп всё» в меню/статус-баре останавливает и музыку; внешняя остановка переводит плеер в
  паузу, а не перескакивает на следующий трек (позиция запоминается и восстанавливается).
* Discord Rich Presence показывает текущий трек и время, пока музыка играет.

## Карта кода

| Файл | Назначение |
| --- | --- |
| `src/music/library.rs` | `music.json`, коллекции (альбомы/плейлисты/треки), статусы, нормализация после сбоя, очистка кэша |
| `src/music/spotify.rs` | разбор ссылок, Web API + публичная страница, очистка названий |
| `src/music/download.rs` | очередь загрузок, каскад SoundCloud → YouTube, проверка длительности |
| `src/music/player.rs` | очередь альбома, Repeat Off/All/One, пауза/перемотка, ожидание загрузки |
| `src/music/tools.rs` | поиск `yt-dlp`/`ffmpeg`, запуск процессов с таймаутом и отменой |
| `src/audio/engine.rs` | `play_with_limit` + `MAX_MUSIC_SECS` (длинные треки) |
| `src/app.rs` | страница «Музыка», плеер, карточка настроек, события загрузок |

## Безопасность и правовые ограничения

* VibeDrop не устанавливает и не обновляет `yt-dlp`/`ffmpeg` сам — только запускает то, что
  установил пользователь. Никакие сторонние установщики не скачиваются.
* Запросы к Spotify идут только на `open.spotify.com`, `accounts.spotify.com` и
  `api.spotify.com`; ссылки на другие хосты отклоняются.
* Скачивание и прослушивание защищённого авторским правом контента регулируется законом вашей
  страны и условиями Spotify/SoundCloud/YouTube. Используйте раздел для личного
  прослушивания контента, который вы вправе копировать. VibeDrop не предоставляет обход
  DRM: он ищет **открыто доступную** копию на открытых площадках.

## Если что-то не работает

| Симптом | Что делать |
| --- | --- |
| «yt-dlp and ffmpeg were not found» | Установите оба, затем укажите пути в *Настройки → Музыка* и перезапустите проверку (измените поле/вернитесь на страницу). |
| Все треки «Ошибка», в причинах «search failed» | Обновите `yt-dlp -U`; проверьте интернет; YouTube может требовать свежую версию. |
| SoundCloud «ничего не найдено», YouTube «длительность не совпадает» | Альбомная версия отличается от сингла; попробуйте импортировать трек отдельно или добавьте источник в `download.rs` (см. ниже). |
| «Spotify did not return metadata» | Изменилась публичная страница. Создайте Client ID/Secret (см. выше) — Web API стабильнее. |
| 401/403 от Spotify | Проверьте ID/Secret; VibeDrop сам попробует публичную страницу. |
| Трек длиннее 15 минут | Ограничение памяти; разбейте микс или слушайте вне VibeDrop. |
| Нет звука только у музыки | Проверьте ползунок в плеере, мастер-громкость и маршрут микрофона (музыка идёт на оба выхода, как звуки). |

## Как добавить ещё один источник

В `src/music/download.rs` каскад описан массивом `attempts`:

```rust
let attempts = [
    (Stage::SoundCloud, "scsearch1:", "", SOUNDCLOUD_TOLERANCE),
    (Stage::YouTube, "ytsearch1:", " official audio", YOUTUBE_TOLERANCE),
];
```

Добавьте вариант `Stage` и строку с префиксом `yt-dlp` (например, `vksearch1:`) и допуском —
остальная логика (проверка длительности, MP3, статусы, отмена) уже общая. Новый `Stage`
нужно добавить в `Stage::label` и в UI-подписи.
